# rdesk V2

rdesk V2 是一个基于 Python、GStreamer 和 WebRTC 的跨平台远程桌面程序。当前版本重点
验证了 **Windows 控制端连接 Ubuntu 20.04 X11 被控端**，Windows 与 Ubuntu 界面均可
选择“被控端”或“控制端”角色。

## 1、软件说明

### 主要功能

- 使用 WebRTC 传输 H.264 桌面视频，支持 NACK、RTX、FEC、PLI 和 GCC 拥塞控制。
- 自动检测 GPU 编码能力；不可用时回退 CPU 编码，兼顾性能与兼容性。
- 支持鼠标、键盘和文本剪贴板远程控制。
- 鼠标坐标按照远端画面的实际显示区域映射，兼容窗口缩放和黑边布局。
- 被控端可设置最大分辨率和最大帧率；连接后控制端可以实时调节，但不能超过被控端上限。
- 分辨率选项根据当前显示器和被控端上限动态生成，最高支持 7680×4320、120 FPS。
- 输入和剪贴板通过 ChaCha20-Poly1305 加密控制通道传输；WebRTC 视频使用 DTLS-SRTP。
- 内置 OFL 许可的 Noto Sans SC 字体，使 Windows 与 Ubuntu 界面字体尽量一致。
- 被控端、控制端以及三种连接方式分别保存配置，互不覆盖。

### 连接方式

| 方式 | 适用场景 | 配置要求 |
| --- | --- | --- |
| 双方地址互认 | 希望被控端只允许指定控制端 | 控制端填写被控端地址；被控端填写允许的控制端地址 |
| 控制端填写被控端 | 局域网、公网 IPv6、端口映射或覆盖网络 | 被控端监听，控制端填写被控端地址 |
| 密钥会合直连 | 两端地址不固定，需要服务器协助发现 | 两端填写相同服务器、房间名和共享密钥 |

会合服务器只交换短期网络地址，不接收共享密钥，也不转发桌面画面。三种连接方式均禁用
TURN 媒体中继；无法建立端到端连接时程序会直接报错。

### 当前运行要求

- Windows：Python 3.10 或兼容版本。
- Ubuntu：推荐 Ubuntu 20.04 X11/Xorg 会话；当前采集链路不支持 Wayland 原生桌面捕获。
- GStreamer 1.28 及 WebRTC、H.264、ICE、DTLS、SRTP、SCTP 相关插件。
- 控制端和被控端必须使用相同的共享密钥，长度至少为 6 个字符。

## 2、配置方法

### 安装与环境检查

Windows：

```powershell
python -m pip install -r requirements-v2.txt
python rdesk_v2.py doctor
python rdesk_v2.py
```

也可以双击 `start_windows.bat` 启动图形界面。

Ubuntu 20.04：

```bash
chmod +x install_ubuntu20_v2.sh start_rdesk_v2_ubuntu.sh
./install_ubuntu20_v2.sh
./start_rdesk_v2_ubuntu.sh doctor
./start_rdesk_v2_ubuntu.sh
```

Ubuntu 安装脚本会把所需运行环境安装到当前用户的数据目录，不会替换系统自带的
GStreamer。`doctor` 输出 `doctor: OK` 后再启动程序。

### 创建配置

1. 启动图形界面，在左侧选择“被控端”或“控制端”。
2. 选择连接方式。
3. 在“配置版本”中输入名称，例如 `default`、`office` 或 `home_pc`。名称只能包含字母、
   数字、短横线和下划线。
4. 填写连接与性能参数。
5. 点击“保存 / 另存”，或直接点击启动按钮。启动时也会保存当前配置。

被控端常用参数：

| 参数 | 说明 |
| --- | --- |
| 监听地址 | 推荐 `::`，在支持的平台上同时监听 IPv6 和 IPv4 |
| 外部信令端口 | 默认 TCP `45000` |
| 控制端口 | 默认 TCP `45001`，传输输入与剪贴板 |
| 内部信令端口 | 默认 `45002`，仅供本机 GStreamer 使用 |
| 显示器 | 要捕获的显示器编号，从 1 开始 |
| 最大分辨率 | 不超过所选显示器的实际分辨率 |
| 最大 FPS | 控制端运行时不可突破的帧率上限 |
| 视频后端 | `auto` 自动选择，也可以强制 GPU 或 CPU |
| 共享密钥 | 至少 6 个字符，必须与控制端一致 |

控制端常用参数：

| 参数 | 说明 |
| --- | --- |
| 被控端地址 | IPv4、IPv6 或域名；裸 IPv6 地址可以直接填写 |
| 信令/控制端口 | 必须与被控端一致 |
| 共享密钥 | 必须与被控端一致 |
| 接收缓冲 | 默认 25 ms；稳定网络建议 20–30 ms，抖动网络建议 40–60 ms |
| 文本剪贴板 | 控制是否同步纯文本剪贴板 |

密钥会合直连还需要填写：

- 自建会合服务器的 IPv4、IPv6 或域名。
- UDP 端口，默认 `45030`。
- 两端完全相同的房间名。
- 本地 UDP 端口；填写 `0` 表示自动选择。

公开版本不预置会合服务器地址。需要会合模式时，在具有公网网络的主机上运行：

```bash
python3 p2p_server.py server --bind :: --port 45030
```

防火墙至少应允许所选网络上的 TCP `45000`、TCP `45001`；会合服务器还需要允许 UDP
`45030`。WebRTC ICE 会使用动态 UDP 端口，因此操作系统防火墙应允许 rdesk/Python 和
GStreamer 进行入站、出站通信。

### 配置文件位置

Windows：

```text
%APPDATA%\rdesk-v2\connections\角色\连接方式\版本.json
```

Ubuntu：

```text
~/.config/rdesk-v2/connections/角色/连接方式/版本.json
```

实际目录结构示例：

```text
connections/
├── host/
│   ├── mutual/default.json
│   ├── direct/default.json
│   └── rendezvous/default.json
└── client/
    ├── mutual/default.json
    ├── direct/default.json
    └── rendezvous/default.json
```

配置 JSON 中包含连接地址和共享密钥，请妥善保护，不要上传到 GitHub、网盘或公开聊天。
仓库的 `.gitignore` 已排除常见配置、环境变量、私钥、日志、缓存和压缩包，但发布前仍应
检查实际提交内容。

## 3、使用样例

以下地址均为示例地址，使用时请替换成自己的实际地址，并设置独立的强共享密钥。

### 样例一：Windows 通过局域网控制 Ubuntu

假设 Ubuntu 被控端局域网地址为 `192.168.1.50`。

Ubuntu 被控端：

1. 选择“被控端”。
2. 选择“控制端填写被控端”。
3. 监听地址填写 `::`。
4. 信令端口填写 `45000`，控制端口填写 `45001`。
5. 选择显示器，设置最大分辨率 `1920×1080`、最大帧率 `30`。
6. 填写共享密钥并启动被控端。

Windows 控制端：

1. 选择“控制端”。
2. 选择“控制端填写被控端”。
3. 被控端地址填写 `192.168.1.50`。
4. 端口和共享密钥填写成与 Ubuntu 相同的值。
5. 点击“启动控制端”。

连接后，可在控制窗口顶部把画面调整为例如 `1280×720 / 20 FPS`。该设置会立即发送给
被控端，但不会超过被控端设置的 `1920×1080 / 30 FPS` 上限。

### 样例二：使用公网 IPv6 并限制控制端

假设被控端地址为文档示例 IPv6 `2001:db8::50`，控制端地址为 `2001:db8::20`。

- 两端都选择“双方地址互认”。
- 被控端的“允许控制端 IP”填写 `2001:db8::20`。
- 控制端的“被控端地址”填写 `2001:db8::50`。
- 两端填写相同端口和共享密钥，然后分别启动。

被控端会拒绝与允许地址不匹配的外部信令和控制连接。

### 样例三：通过自建会合服务器发现对端

假设会合服务器使用文档保留地址 `203.0.113.10`。

服务器端：

```bash
python3 p2p_server.py server --bind :: --port 45030
```

控制端与被控端：

1. 都选择“密钥会合直连”。
2. 会合服务器填写 `203.0.113.10`，端口填写 `45030`。
3. 房间名填写相同值，例如 `example-room`。
4. 填写相同的强共享密钥。
5. 先启动被控端，再启动控制端。

服务器只帮助双方交换可达地址；认证信令、控制数据和桌面视频仍在两端之间传输。

### Ubuntu 登录后自动启动被控端

先在界面中保存并验证被控端配置，然后编辑
`rdesk-v2-host-autostart.desktop.example`，将其中的 `/opt/rdesk` 替换为项目实际绝对
路径，再安装自启动文件：

```bash
mkdir -p ~/.config/autostart
cp rdesk-v2-host-autostart.desktop.example ~/.config/autostart/rdesk-v2-host.desktop
chmod +x ~/.config/autostart/rdesk-v2-host.desktop
```

下次进入 X11 桌面后，程序会使用已保存的被控端配置自动启动。
